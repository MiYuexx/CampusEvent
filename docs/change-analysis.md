## 2. 受影响模块

| 层次 | 涉及类/接口/数据库对象 | 影响说明 |
| --- | --- | --- |
| 策略层 | RegistrationPolicy 及具体实现 | 若报名规则变化，评估扩展新策略实现 |
| 通知层 | EventDispatcher、EventObserver、MessageObserver | 若新增通知渠道，新增观察者实现 |
| 业务层 | RegistrationService | 状态流转、名额与校验规则是否调整 |
| 数据层 | Activity / Registration / Message 表 | 是否需要新增字段或关联表 |
| 接口层 | routes.py 与前端页面 | 是否新增/修改接口与展示项 |

## 3. 设计决策

- 优先遵循开闭原则：能通过新增策略/观察者实现的变更，不修改主报名流程。
- 若变更涉及公共规则，再调整 `RegistrationService`，并补充对应单元测试。
